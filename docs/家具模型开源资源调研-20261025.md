# 开源家具模型资源调研与接入方案

日期：2026-10-25
目标：给「等距 2.5D 小屋」扩充家具库，优先 **CC0 / 可商用 / 适合移动端** 的资源。

---

## 0. 先说结论

**推荐主用：KayKit Furniture Bits + Kenney Furniture Kit。**
两者都是 CC0、低多边形、专为游戏/移动端优化，适合先转成等距 2D 精灵，再接进现有 SVG/DOM 房间引擎。

- **KayKit Furniture Bits 1.0**：50+ 件，实际仓库里我数到 **53 个 glTF**，另有 OBJ/FBX；单张 1024 渐变图集，可降到 128；CC0，无需署名。[KayKit 仓库](https://github.com/KayKit-Game-Assets/KayKit-Furniture-Bits-1.0)[cite:0d6fc1f0-2]
- **Kenney Furniture Kit**：3D、**140 个文件**、CC0；覆盖面广，适合补齐桌椅床柜灯。[Kenney 页面](https://www.kenney.nl/assets/furniture-kit)[cite:68404934-4]
- **Poly Haven**：家具分类下模型全部 **CC0**，写实 PBR、面数偏高；适合少量「主角家具」预渲染，不适合 40 件全量运行时加载。[Poly Haven License](https://polyhaven.com/license)[cite:0d6fc1f0-1]
- **Poly Pizza**：10000+ 低模，GLB/FBX，逐件 **CC0 或 CC-BY 3.0**，商用可以，但 CC-BY 必须署名。[Poly Pizza 概览](https://designblocs.com/resources/source/poly-pizza)[cite:4e04e810-2]
- **Quaternius Furniture Pack**：23 件，FBX/OBJ/Blend；许可为 QAL：免费商用、免署名，但**禁止把素材本身转售/再分发**。公开仓库里直接放原始 GLB 有风险，建议只放预渲染结果或先确认授权。[Quaternius 包](https://quaternius.com/packs/furniture.html)[cite:68404934-1] [QAL](https://quaternius.com/license.html)[cite:73e4b0e9-1]
- **OpenGameArt「Isometric Furniture and Walls」**：2D 等距像素家具+墙，**CC0**，可直接当精灵用；但像素风和现在的纸模型风不一致，适合做「像素主题」而不是默认家具。[OpenGameArt](https://opengameart.org/content/isometric-furniture-and-walls)[cite:d27bc09c-2]
- **Khronos glTF Sample Assets**：有高质量沙发/家具样品，但展示集多为 **CC BY 4.0**，必须署名；PBR 扩展多、面数高，适合做测试/单件 hero，不适合批量。[Sofa 示例](https://github.com/KhronosGroup/glTF-Sample-Assets/blob/main/Models/GlamVelvetSofa/README.md)[cite:73e4b0e9-2] [Showcase 许可](https://raw.githubusercontent.com/KhronosGroup/glTF-Sample-Assets/main/Models/Models-showcase.md)[cite:91f4f7bc-1]

## 1. 为什么不能直接“把 GLB 丢进房间”

当前房间是 **SVG/DOM 等距渲染**，不是 WebGL：

- `CAT` 里每件家具是一个 `draw()`，返回 SVG 片段；
- `renderFurniture()` 把 SVG 塞进 `.rv-furn`；
- 占格、拖拽、翻转、点击命中全部按 DOM/SVG 做；
- 光照、夜景遮罩、接触阴影都是 CSS/SVG。

如果直接引入 Three.js + GLTFLoader：

- 需要新增 WebGL 渲染层，和现有 SVG 场景合成；
- 家具点击/拖拽/占格要从 Three.js 射线反算，现有逻辑得再写一套；
- 移动端首帧、内存、发热都会明显上升；
- 两套渲染的明暗/描边/色温很难统一。

**结论：保留现有 SVG 场景，把 3D 模型预渲染成等距 2D 精灵。**
这也符合现在的「纸模型 + 柔光」美术方向。

## 2. 推荐管线：CC0 3D → 等距精灵

### 2.1 资产处理

1. 取 KayKit / Kenney 的 glTF/FBX/OBJ。
2. Blender 无头脚本统一：
   - 正交相机；
   - yaw = 45°（或 0/45/90/… 共 4~8 个角度）；
   - pitch = 30°（与现有 `P()` 的 2:1 等距一致）；
   - 透明背景，关闭烘焙阴影；
   - 每件模型归一化到 **1 格 = 48×24 场景像素** 的包围盒；
   - 输出 256×256（2x 为 512）WebP/PNG。
3. 每件家具输出一张精灵图或打进 2048 图集：
   - `frames`: 4 或 8 个朝向；
   - `anchor`: 脚底中心 `[0.5, 1]`；
   - `wTiles/dTiles`: 占格；
   - `height`: 显示高度（用于 z-index 和气泡）。
4. 引擎侧保留现有：
   - `.rv-furn` 的 `translate(-50%,-100%)`；
   - `drop-shadow` + 脚底接触阴影；
   - 翻转用 `scaleX(-1)`，不再额外烘焙镜像。

### 2.2 数据模型

在 `CAT` 里新增 `sprite` 类型，不动存档主体：

```js
armchair: {
  n: '扶手椅', cost: 32, cf: 3, lv: 1, act: '坐下',
  sprite: {
    src: 'assets/furniture/kaykit/armchair.webp',
    frames: 8, cols: 8, rows: 1,
    anchor: [0.5, 1],
    footprint: [1, 1],
    height: 1.0
  }
}
```

`furnSVG()` 增加分支：

```js
if (c.sprite) {
  return '<div class="rv-sprite" style="'
    + 'background-image:url(' + c.sprite.src + ');'
    + 'background-position:' + framePos + ';'
    + '"></div>';
}
```

`r` 从 0/1 扩展成 `rot: 0..7`；旧的 `r=1` 仍按镜像处理，保证旧存档兼容。

### 2.3 性能预算

- 首包**不要**塞全部图集：按需 JSON + 分图集懒加载。
- 建议第一批 12 件 × 4 朝向 × 192px WebP，控制在 1.5–3MB。
- 每件 8 朝向只给「座椅/床」这类会转的；柜子/挂画 2–4 朝向足够。
- 图集单张 ≤ 2048，移动端 GPU 更稳。
- 像素画仍走现有 `pixRects`，不受影响。

## 4. 许可与仓库规范

公开仓库建议只收 **CC0**：

- KayKit：CC0，建议署名（非强制）。
- Kenney：CC0。
- Poly Haven：CC0。
- OpenGameArt 该 2D 包：CC0。
- Poly Pizza：**逐件看**；CC0 可用，CC-BY 3.0 必须署名。
- Khronos 展示集：多为 CC BY 4.0，必须署名。
- Quaternius QAL：免费商用、免署名，但**禁止再分发素材本身**；公开仓库不要直接放原始包。

落地文件：

```
assets/furniture/
  kaykit/…
  CREDITS.md          # 来源 URL、作者、许可、下载日期、文件 hash
  LICENSE-KayKit.txt
  LICENSE-Kenney.txt
```

`CREDITS.md` 示例：

```md
## KayKit Furniture Bits 1.0
- Author: Kay Lousberg — https://kaylousberg.com
- Source: https://github.com/KayKit-Game-Assets/KayKit-Furniture-Bits-1.0
- License: CC0 1.0 — https://creativecommons.org/publicdomain/zero/1.0/
- Used files: Assets/gltf/armchair.gltf ...
- Downloaded: 2026-10-25
```

即使 CC0 不要求署名，也建议保留来源，后续换包/排查版权时能说清楚。

## 5. 不建议的方案

- **直接运行时加载 GLB + Three.js**：为了 20 件家具引入整套 WebGL，收益低、回归面大。
- **把 Sketchfab 上“免费下载”当开源**：免费 ≠ 可商用/可再分发，必须逐件看许可。
- **Quaternius 原始包直接进公开仓库**：QAL 禁止再分发素材本身，容易踩线。
- **直接用写实 PBR 模型缩小**：和现在的纸模型/柔光风格冲突，且面数高。

## 5.7 比例校准：参考项目与规则

### 之前为什么失衡

每件精灵在渲染时都被「水平最大边缩到 1 格」，再在 CSS 里逐件手调 0.34–0.55。结果：

- 3m 沙发和 0.75m 凳子被拉成同一量级；
- 床、地毯、长餐桌偏小，圆凳、边柜偏大；
- 摆进房间后占地与视觉尺寸对不上。

### 参考

- [hazhirrashidi/floorplan-3d](https://github.com/hazhirrashidi/floorplan-3d)：纯 HTML/CSS/JS + Three.js，2D 画户型 → 实时 3D 走查；强调 snap-to-grid、尺寸标注、真实比例。
- [laanlabs/openPlan3D](https://github.com/laanlabs/openPlan3D)：SvelteKit + Three.js 的 2D/3D floor plan editor，支持家具目录、移动/旋转/缩放/锁定与尺寸显示。
- [charmlinn/blueprint3d-modern](https://github.com/charmlinn/blueprint3d-modern)：Three.js + TypeScript，家具目录按类别浏览，实时尺寸、旋转/缩放/锁定。
- [jiexiya.vip · 我的家 3D 空间](https://jiexiya.vip/)：写实家居漫游，重点是自然材质、柔和日光、真实家具尺度。我按这个方向把精灵降低饱和度、保留真实米制比例；如果你说的「jie跃」是另一个站点，发我链接再对齐。

### 现在的规则

1. **模型单位按米处理**，不再逐件缩到 1 格。
2. 固定渲染视野 **4.6m**，1m ≈ 55.65px；输出裁掉透明边。
3. 引擎统一显示缩放 **0.64** → **1 格 ≈ 1.35m**。
4. `CAT` 里登记真实占地（2×2 / 3×2 …），摆放、碰撞、z-index 都用它。
5. 精灵色彩统一加 `saturate(.78) contrast(.96)`，减少 KayKit 原色的玩具感。
6. 后续新增模型只改 `w/d`，不再手调每件 scale。

## 6. 建议的下一步

1. 先落地 KayKit 的 12 件，按 4 朝向 192px 预渲染，做一个 `sprite` 分支验证点击/拖拽/占位/翻转。
2. 验证通过后，再补到 30–40 件；按品类拆 2–3 张图集，懒加载。
3. 如果 sprite 效果满意，再考虑把现有 21 件程序化家具逐步替换成同一套预渲染资产。
4. 所有新增资产在 `CREDITS.md` 登记；CC-BY 资产在「设置 → 关于」加署名入口。
