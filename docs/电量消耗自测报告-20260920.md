## 三、结果解读：为什么是「数据不足」

- 判定条件：各段样本都不足 5 分钟（电量颗粒度为 1%，样本太短算不出可信速率）。
- 本次环境必然导致该结果：
  - 设备接通电源 → 有 4 分钟落在「充电中」，按设计整段剔除；
  - 自动化浏览器页面全程「不可见」→ 绝大部分时间被系统按「页面未运行」记账（11 分钟），前台样本 0 分钟；
  - 窗口内电量 95% → 95% 没有下降，进一步无法算出耗电速率。
- 结论：报告如实标注「数据不足」符合工具设计，不代表工具异常。本轮的验证重点是链路：
  入口 → 开始测 → 刷新续测 → 到点自动出报告 → 结论与建议落盘，全部通过。

## 四、真机复测建议

- 在手机上**拔掉充电器**跑一轮；追求准确度用「过夜 8 小时」档，15 分钟档只看趋势。
- 对照口径：页面未运行 ≤2 正常 / 2~6 偏高 / >6 异常；后台页面自身（开后台保活时）参考同口径。
- 想测「后台保活」的实际开销：开启后台保活后把页面切出去放着跑一段，看「后台页面自身」那一行。
