日期：2026-10-25

**效果预览**：`docs/room-preview/preview-sheet.png`（六套风格合图）；单页 `docs/room-preview/index.html`；重新生成 `npm run preview:room`。

**家具扩充**：`docs/家具模型开源资源调研-20261025.md`（CC0 来源、许可、3D→等距精灵管线）。

## 一、这次到底改了什么

房间不是「再修几个 bug」，而是把**数据、几何、渲染、交互**四层拆开：

```
用户输入 / 导入 JSON / 旧存档 / IndexedDB
                │
                ▼
        room-core.js（纯函数，无 DOM、无存储）
        ├─ normalize / parse / serialize
        ├─ 版本迁移 v2 → v6
        ├─ 颜色 / 名字 / ID / 像素画 / 组装件白名单
        ├─ 占格判定 itemAt / canPlace
        └─ 数值边界与容量上限
                │
                ▼
        room-iso.js（只做渲染与交互）
        ├─ SVG 等距场景、家具/TA/灯光
        ├─ 相机手势、放置/移动、装修模式
        └─ 面板、画室、组装台
                │
                ▼
        activeStore + IndexedDB 镜像
```

`room.js` 是旧引擎，只在 `room-iso.js` **完整初始化成功后**才让位；新引擎若因缺依赖或异常没有跑到最后一行，旧引擎会接管，不再出现「两套都不工作」的死屋。

## 二、已定位的底层问题（按风险排序）

### 1. 数据写回没有「可信边界」：一次坏读会抹掉整屋

旧 `load()` 读空就回落 `fresh()`，随后任何 `save()` 都会整包写回。localStorage 配额满、隐私模式、IndexedDB 回填未完成、JSON 损坏，都会让「读不到」被当成「确实没有」。

**现在**：

- `Core.parse()` 区分 `absent`（确实没有）和 `corrupt`（有内容但解析失败）。
- `roomLoadUncertain`（数据层没就绪 / 该键读不出）与 `roomReadOnly`（坏档）都会**拒绝整包写回**。
- 坏档不会被 fresh 覆盖；界面提示只读，用户可主动导入备份或重置。
- 恢复完成（`mochi-restore-done`）后按权威值重载。
- 所有写入统一走一个 `save()`，不再散落 `s.set(...)`。

### 2. 外部 JSON 直接把颜色/名字拼进 SVG 和 innerHTML

导入的房间 JSON 里，`fill`、`background`、家具名都会原样进入 `innerHTML`。一个 `"` 就能从颜色属性里逃出来。

**现在**：

- 颜色只接受 `#rgb` / `#rrggbb`，其余一律回落默认值。
- 名字去掉 `< > & " '` 与控制字符，渲染时再 `esc()` 一次。
- 像素画调色板逐色校验；非法色对应的格子直接透明。
- 组装家具只允许 `box / ball / cyl`，坐标、尺寸、颜色全部钳制。
- 类型、ID、仓库键、地板格键全部白名单化，`__proto__` 之类进不来。

### 3. 渲染层会拿到 `null` 然后整段崩

`catOf(t)` 对未知类型返回 `null`，`furnSVG()` 直接 `c.draw()`；导入一份带未知家具的存档就能让房间白屏。

**现在**：

- `pruneUnknown()` 统一清掉未知家具、悬空自定义件、失效 `lit`。
- `furnSVG()` / `furnArtSVG()` / `asm2SVG()` 都有空值兜底。
- 自定义家具 ID 只从 `Object.prototype.hasOwnProperty` 取，不再走原型链。

### 4. 墙面件被当成地板占格

旧 `itemAt()` 遍历全部 `d.fx`，窗户、挂画、门也参与地板碰撞——窗下永远放不了东西。

**现在**：`Core.itemAt(fx, x, y, isWallType)` 跳过墙面件；放置、移动、拖动预览、格子高亮全部共用这一套。

### 5. 视角每次操作都被重置

`renderAll()` 末尾无条件 `fit()`，于是开灯、换装、摆家具、调亮度都会把用户双指缩放/平移的视角拉回默认。

**现在**：`renderAll()` 不再动相机；只有户型/墙高/导入这类改变场景尺寸的操作显式 `renderAll({fit:true})`。

### 6. 墙面件拖动整段是坏的

`wdrag` 在手势代码里被写成了 `wdraj`，`pointermove` 第一行就抛 `ReferenceError`；装修模式下立即起拖还因为对象尚未赋值而直接返回。

**现在**：拼写修正；装修模式同步起拖；屏幕位移按相机缩放折算成场景像素；墙被删除时自动把窗/门/挂画迁到仍然存在的墙（`repairWallRefs()`）。

### 7. 装修「保存」其实没有事务

旧实现每个操作都立刻 `save()`，点「取消/退出」也不会回滚；地板拖动每刷一格还往撤销栈塞一份全屋快照，40 步瞬间被刷满。

**现在**：

- 进入装修先存一份 `decoBase` 快照。
- 装修期间 `save()` 只标脏，不落盘。
- 点「保存」才 `save({commit:true})`；点「取消 / Esc / 返回」整份回滚。
- 地板一次拖动只记一步撤销。
- 装修期间 TA 行为暂停，避免和事务打架。

### 8. 其他顺手修掉的确定性问题

| 问题 | 结果 |
|---|---|
| `el.className` 写 `r-flip`，CSS 是 `rv-r-flip` | 家具「翻转」从来没生效 → 已修 |
| 商店未解锁徽章显示 `Lv.价格` | 改为 `Lv.等级` |
| 画室尺寸按钮切 `on`，CSS 是 `rv-on` | 当前画布尺寸高亮不更新 → 已修 |
| 墙面菜单「换到另一面墙」只改 `x` | 对带 `geo/wp` 的窗/门是空操作 → 改为真正换 `side` 并钳制 `t` |
| `resizeRoom` 只检查左上角 | 大件家具会伸到房间外 → 按完整占格检查，超界收回仓库 |
| 墙高/户型变化后场景不重新适配 | 会裁掉半截屋子 → 显式 `fit` |
| `matchMedia(...).addEventListener` 老 WebKit 无此方法 | 房间初始化可能整段失败 → 保留调用但由整体 try/catch 隔离；后续可加 `addListener` 降级 |

## 三、数据模型 v6

顶层字段（全部经过 `Core.normalize`）：

| 字段 | 说明 |
|---|---|
| `schema` | 当前 6；迁移在 core 内完成 |
| `cols` / `rows` | 4–10 / 3–8 |
| `wallH` | 100–220 |
| `fx[]` | 家具实例：`i,t,x,y,w,d,r,vs,sc,geo,wp,fc,open` |
| `inv` | 仓库，数量 0–99 |
| `lit` | 只保留仍然在场的家具 ID |
| `walls` | `L/R` 必有，`F1/F2` 可空；颜色 + 像素纹样 |
| `fcells` | 地板单格上色，键必须是界内 `x,y` |
| `look` / `lookArt` | 换装与手绘层 |
| `customFurn` | 手绘 / 组装家具，最多 120 件 |
| `style` / `accent` | 美术风格与强调色（新增） |
| `ta` | 位置、目标、动作、下次行为时间 |
| `px/level` | `pts` 0–1e8，`lv` 1–5 |

**不变量**（core 保证）：

1. 任何输入都不会让 `normalize()` 抛异常。
2. 输出永远有完整 `fx/inv/lit/walls/look/customFurn/ta`。
3. 家具 ID 唯一；`lit`、`inv` 不引用不存在的件。
4. 所有颜色是可安全插入 SVG 的 `#rrggbb`。
5. 所有名字不含 HTML 元字符。
6. 所有坐标在户型内；`w/d` 不越界。
7. 像素画 `s ∈ [4,48]`，调色板 ≤ 250，格子索引必须落在调色板内。
8. 组装件 ≤ 80 个，形状/尺寸/颜色都有上限。

## 四、美术重新规划

### 4.1 之前的问题

- 颜色没有体系：墙纸、地板、按钮、选中态、强调色各自硬编码，换一套墙纸后 UI 仍然是紫色。
- 光只有「夜晚遮罩」，没有环境光、接触阴影、墙角过渡，家具像贴纸。
- 场景与 UI 的层级糊在一起：状态条、控制条、场景都靠 `margin` 挤，手机上场景被压得很矮。
- 风格只有「米白 / 暮色 / 星空 + 木地板 / 棋盘砖」，很难表达房间性格。

### 4.2 新方向：**「有光的纸模型小屋」**

不是写实渲染，也不是纯像素，而是：

- **纸模型**：低多边形体块 + 柔和接触阴影 + 少量手绘纹理。
- **有光**：顶部窗光、墙脚环境遮蔽、夜晚暖灯/冷月光两套色温。
- **可换气质**：同一套几何，靠墙/地板/点缀色换出完全不同的房间。

### 4.3 色板（6 套整体风格）

| 风格 | 墙 L / R | 地板 | 点缀色 | 气质 |
|---|---|---|---|---|
| 奶油原木 | `#F7EFE2` / `#EADCC8` | 木地板 | `#B98A5E` | 默认，温暖、耐看 |
| 雾蓝晨光 | `#E8EFF6` / `#D7E3EE` | 浅灰石 | `#6E8CA8` | 清晨、安静 |
| 暮色玫瑰 | `#F4DFE3` / `#E8CBD2` | 木地板 | `#C07D8C` | 柔软、私密 |
| 苔原森居 | `#E6EDE0` / `#D5E0CC` | 榻榻米 | `#7C9670` | 植物、慢生活 |
| 陶土黄昏 | `#EFE1D2` / `#E1CDB9` | 木地板 | `#B5734E` | 黄昏、手工感 |
| 午夜星蓝 | `#3C406B` / `#31355A` | 浅灰石 | `#8A7BD8` | 夜晚、星光 |

落地方式：

- 数据只新增 `style` + `accent`；墙色/地板仍写回原有字段，旧存档零迁移。
- 「装修 → 整体风格」一次换墙 + 地板 + 点缀色；手动改墙/地板会自动标记为「自定义」。
- 强调色通过 `--rv-accent` 注入页面，按钮、开关、滑条、选中态、装修保存键全部跟随。

### 4.4 场景光

静态场景新增（全部是 SVG 渐变，不增加节点数量级）：

1. **地面渐隐**：靠窗一侧偏暖亮，前景压深，避免地板一整块死色。
2. **墙面上下明暗**：左墙暖、右墙冷，墙角加一条软阴影，两面墙不再硬拼。
3. **墙脚阴影 + 踢脚线高光**：家具落地更稳。
4. **场景环境光**（CSS 伪元素）：顶部窗光 + 四周轻暗角；夜间切换为冷月光。
5. **家具接触阴影**（CSS 伪元素）：每件家具脚底一层柔和椭圆，和 SVG 投影叠加。

### 4.5 UI

- 控制条改成悬浮纸片：圆角 18、毛玻璃、统一阴影；小屏自动压缩。
- 状态条同样纸片化，不再是一条横贯屏幕的灰条。
- 弹层统一圆角/阴影/标题留白；分区线使用统一 hairline。
- 装修操作台把「保存」做成强调色实心键，「取消」与「撤销」并列，语义明确。
- 所有强调色都走 `var(--rv-accent)`，深色模式单独给一套更亮的 accent。

### 4.6 动效与性能

- 保留 TA 走路 bob、烛火、灯晕；`prefers-reduced-motion` 全部关闭。
- 静态场景只做一次 `innerHTML`；像素画仍按行合并同色格（满画 32×32 从 1024 节点降到几十个）。
- 相机变换用 `translate + scale`，不触发重排。
- 家具 SVG 外观签名不变就不重建。

### 4.7 后续美术路线（不阻塞本次）

1. 把程序化家具拆成「体块 + 材质 + 描边」三层，统一 6 套材质的明暗公式。
2. 增加窗光投影到地板的动态多边形（按窗户 `geo` 算，不用贴图）。
3. 家具图标从 emoji 迁移到统一线性图标（与底部控制条一致）。
4. 立绘/家具贴图若引入，统一 2x PNG/WebP + `image-rendering: pixelated` 仅用于像素画。

## 五、风险隔离清单

| 风险 | 隔离手段 |
|---|---|
| 新引擎报错导致房间全废 | `__roomIso` 只在文件末尾置位；`room.js` 兜底 |
| 数据层未就绪 → 空存档覆盖 | `roomLoadUncertain` + `roomReadOnly` + 恢复事件重载 |
| 导入恶意 JSON | 颜色/名字/类型/尺寸白名单，渲染前 `esc()` |
| 未知家具类型白屏 | `pruneUnknown` + 渲染空值兜底 |
| 装修误操作 | 快照事务 + 保存/取消 + 单步撤销 |
| 相机跳动 | `renderAll` 不再 `fit` |
| 墙面引用失效 | `repairWallRefs()` 在载入、缩放、删墙后执行 |
| 大存档卡顿 | 家具 80 / 自定义 120 / 组装件 80 / 画布 48 上限 |

## 六、验证

```bash
node tools/verify-room-core.mjs      # 74 条纯数据断言
node tools/verify-room-iso.mjs       # 17 条浏览器冒烟（需本机 Chrome/Edge）
npm run preview:room                 # 重新生成 docs/room-preview/ 六套效果图
node build.mjs                       # 重新生成 index.html 与 js/
```

`tools/verify-room-core.mjs` 覆盖：

- 脏数据（null / 数组 / 字符串 / `fx:[null]`）不抛异常
- v2 像素画、v4 窗户迁移
- 颜色/名字/HTML 注入
- 重复 ID、悬空仓库、失效 `lit`
- 墙面件不占地板格、叠放开关
- 数值边界、容量上限
- 序列化/解析/幂等
- 组装件白名单

浏览器侧新增 `node tools/verify-room-iso.mjs` 覆盖：新引擎接管、7 件初始家具、TA/HUD 渲染、相机不被 render 重置、save/reload、墙面件不占地板格、装修取消回滚 / 保存落盘、墙面拖动换位、无运行时异常。

旧的 `verify-room.mjs` 针对旧引擎的 `.r-*` 选择器与 `window.__roomState`，在新引擎下会大面积失败，属于测试代际问题，不代表房间回归；等距房间以 `verify-room-iso.mjs` 为准。
