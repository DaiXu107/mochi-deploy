# 2D 画户型 → 3D 小屋：可行性评估

日期：2026-10-25
结论：**可行，建议分三级做，不要一步上完整 Three.js 户型编辑器。**

---

## 0. 先看现在的房间引擎

当前房间不是 3D 引擎，而是：

- 矩形网格：`cols × rows`（4–10 × 3–8）
- 两面后墙 `L/R` + 可选两面前半墙 `F1/F2`
- 家具是网格坐标 + `w/d` 占地 + SVG/等距精灵
- 墙体/窗/门用墙面局部坐标 `side + t`
- 渲染是 SVG + DOM，不是 WebGL

所以「2D 画户型」能不能接，取决于画出来的东西是不是**轴对齐矩形/网格墙**。

---

## 1. 方案 A：网格户型编辑器（推荐先做）

**做法**：新增一个 2D 俯视编辑页，直接编辑现有数据：

- 拖动边界改 `cols/rows`
- 点格子画/擦墙体
- 门窗挂在墙面 `L/R/F1/F2 + t`
- 家具用现有网格 + 占地
- 保存后切回现有 3D 小屋，不改渲染器

**能实现的体验**：

- 画矩形卧室 / L 形房间（用半墙拼）
- 加门、窗、地板分区
- 家具吸附网格、显示尺寸、旋转
- 2D/3D 一键切换

**工作量**：中小。新增一个页面 + 触摸绘制 + 撤销栈；现有 `Core` 数据层已经能承载大部分字段。

**风险**：低。数据仍是同一套，旧房间不用迁移。

---

## 2. 方案 B：任意多边形户型（真正的「画户型」）

**做法**：把墙体从「两面后墙 + 半墙」升级成线段集合：

```js
plan = {
  walls: [
    { id, x1, y1, x2, y2, h, thickness, openings: [
      { kind: 'door'|'window', t, w, h, sill }
    ]}
  ],
  rooms: [
    { id, polygon: [[x,y], ...], floor: '#...' }
  ]
}
```

渲染方式三选一：

1. **SVG 等距挤出**（保留当前无 WebGL 架构）：墙线段按等距投影挤成多边形，地板用多边形填充；门窗在墙段局部坐标上开口。能保持现在的 2.5D 纸模型风。
2. **Canvas 2D 等距绘制**：同上，但绘制性能更可控，适合很多墙段。
3. **Three.js**：真正的 3D，墙体挤出、GLB 家具、第一人称漫游；但和现有 SVG 引擎是两套渲染。

**工作量**：中大。主要成本不在画墙，而在：

- 任意墙段的等距投影、遮挡排序、门窗开洞
- 家具从「网格占格」变成「可自由摆放 + 碰撞」
- 旧存档迁移（矩形房间 → 4 段墙）
- 相机、点击命中、移动端手势

**风险**：中高。建议用 feature flag 隔离，旧房间继续走现有引擎。

---

## 3. 方案 C：完整 3D 走查（像 floorplan-3d / openPlan3D）

**做法**：Three.js + 墙体挤出 + GLB 家具 + 第一人称/俯视相机。

**适合**：想要「在房间里走一遍」、真实材质、动态灯光。
**不适合**：当前以手机 WebView、低配安卓、离线 PWA 为主的使用场景；WebGL 首帧、内存、发热都明显高于 SVG。

**参考项目**：
- [hazhirrashidi/floorplan-3d](https://github.com/hazhirrashidi/floorplan-3d)：纯 HTML/CSS/JS + Three.js，2D 画户型 → 实时 3D 走查。
- [laanlabs/openPlan3D](https://github.com/laanlabs/openPlan3D)：SvelteKit + Three.js，2D/3D floor plan editor。
- [charmlinn/blueprint3d-modern](https://github.com/charmlinn/blueprint3d-modern)：Three.js + TypeScript，家具目录、旋转/缩放/锁定、尺寸。

---

## 4. 建议路线

**A 已落地；下一步是 B 的墙体部分，最后才考虑 C。**

1. **A（1 个版本）**：2D 网格户型页 + 拖动边界 + 门窗 + 切回现有 3D。
2. **B（独立功能开关）**：墙段数据 + SVG 等距挤出 + 多边形地板 + 自由家具摆放。
3. **C（可选）**：Three.js 3D 走查，作为「效果图/漫游」模式，不替换日常房间。

### MVP 验收

- 画一个矩形房间，加一扇门两扇窗
- 2D ↔ 3D 切换，尺寸一致
- 家具按真实占地摆放、旋转、拖动
- 撤销/重做、保存/刷新不丢
- 旧存档不迁移也能打开

### 不做什么

- 第一版不做任意角度墙 + 自动闭合房间
- 第一版不做真实材质/全局光照
- 第一版不把现有 SVG 房间整体替换成 Three.js

---

## 4.5 已落地 MVP（2026-10-25）

房间底部新增 **户型** 按钮，打开 2D 网格户型页：

- 2D 俯视：地板格、后墙 L/R、可选前左/前右半墙 F1/F2
- 拖右侧 / 下侧紫色把手改 `cols/rows`，松手才真正应用（拖动中只预览，缩小不会误删家具）
- 「装门 / 开窗」：点墙线加门/窗（扣点，和 3D 装修同价）
- 「地板」：点格子刷色 / 恢复
- 「擦除」：点家具、门窗或地板格删除
- 「选择」：直接拖动家具（按 `w×d` 碰撞）；点家具选中
- 「看 3D」：切到现有 3D 小屋查看草稿，底部「返回 2D 户型」
- 「保存」：提交并落盘；「取消」：整份回滚（户型、家具、点数、门窗全部还原）

数据仍是现有 `room-data`，没有新增存储键；旧存档直接打开。限制：第一版只支持轴对齐矩形户型 + 半墙，不支持任意角度内墙；后者属于方案 B。

## 5. 结论

- **网格 2D 户型 → 现有 3D**：已落地（底部「户型」按钮）。
- **任意多边形 2D 户型 → 3D**：可行，但需要重写墙体投影/遮挡/碰撞，属于独立大版本。
- **完整 3D 走查**：技术可行，但会引入 Three.js 和 WebGL 的移动端成本，建议作为可选模式，而不是默认房间。
